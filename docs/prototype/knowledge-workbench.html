Rust 借用

技术 / Rust 借用 · 418 字 · 3 天前更新

借用检查器在编译期判断引用是否悬垂，代价是学习曲线陡。它用前期的摩擦换后期几乎不需要排查内存类 bug。

两条规则

  • 同一时刻，要么有任意多个不可变借用，要么有唯一一个可变借用。
  • 引用的存活时间不能超过它指向的值。

典型会被拦下的例子：

fn bad() -> &String { let s = String::from("hi"); &s }

和生命周期标注的关系

生命周期标注不是让引用活得更久，而是告诉编译器「这个引用和那个值一样长」，它只参与检查，不改变运行期行为。

rust-lifetimes.md readonly 
# Rust 生命周期速查

- 标注语法：fn f<'a>(x: &'a str) -> &'a str
- 省略规则：单入参时，输出引用沿用入参的生命周期
- 结构体持有引用必须标注：struct S<'a> { s: &'a str }

## 什么时候需要手写
1. 多个入参引用，返回值是引用
2. 结构体/枚举里存引用
3. 需要表达「返回值的生命周期与某个入参绑定」

这版设计的取舍

DESIGN NOTES · 2026-11-13

1. 三栏 + 知识树当首页
左（文件/对话/笔记）· 中（知识树 / 笔记 / 文件）· 右（Agent）。中间默认是知识树，点任何节点或文件就切成内容视图，返回箭头回树。这样「首页」和「浏览」是同一个地方，不用两套导航。
2. 树的展开规则（按你的描述）
中心圆点＝知识库根。悬停它 → 一级目录以半透明浮现（只预览，不固定）；点击它 → 一级目录实体化，并把「没有父级的散记」作为卫星点一起放出来；点击某个一级目录 → 展开它的子级，再点收起。笔记节点显示为实心小点，目录显示为空心圈，一眼能分开。
3. 空库不做「空状态插图」
做一片缓慢漂移的星海（canvas 粒子 + 近距连线 + 鼠标涟漪），文案只有一句「写下第一句，它会成为这片星海里的一颗」。想更重的话可以换成 3D：vasturiano/3d-force-graph（6.5k★，ThreeJS）做真正的力导向星空。
4. Agent 面板的「上下文」是可见的
顶部固定一行 chip：当前文档 + 选中的段数，可以逐个移除。这是之前对比里 A 方案（NotebookLM）最值得抄的一点——用户永远知道 AI 看到了什么。
5. 视觉方向
暖白纸感 + 单一赭色强调 + 等宽小字做元数据，不用卡片阴影堆叠。右上角可切深色（midnight），两套都做完了。
三点需要你拍板：
① 左栏「对话」指的是 AI 会话列表（现原型），还是保留的社交聊天？
② 「允许修改」开关的粒度：整轮授权（现在这样），还是每次改动都点「应用」？
③ 知识树默认要不要显示笔记的「最近打开」高亮，还是保持纯结构？
